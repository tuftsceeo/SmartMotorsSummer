# Smart Motor for Spike Prime - Integration Guide

## Overview

This implementation adapts the Smart Motor interface (originally for ESP32 devices over WebUSB) to work with LEGO Spike Prime robots over Bluetooth Low Energy (BLE). It provides three modes:

1. **Explore** - Real-time interactive motor and sensor control
2. **Train** - Build a dataset of sensor-motor training pairs
3. **Play** - Run a k-NN (k-nearest neighbor) program that autonomously controls the motor based on sensor readings

## Files Created

### Core Components
- `SmartMotorSpike.jsx` - Main React component with UI
- `smartMotorUtils.js` - Utilities for program generation and data parsing
- `spike_continuous_control.py` - (Reference) Python program for continuous monitoring

## How It Works

### Architecture

The system uses a **rapid program update** approach:

1. **Explore/Train Modes**:
   - When the user moves the motor slider, a small Python program is generated
   - This program sets the motor to the target position and reads the sensor
   - The program is uploaded to the Spike Prime and executed
   - Sensor readings are sent back via console notifications
   - Debouncing (500ms) prevents too many uploads

2. **Play Mode**:
   - A complete k-NN program is generated from the training data
   - This program runs continuously:
     - Reads sensor values
     - Finds the nearest training data point
     - Moves motor to the corresponding position
   - Updates are sent via console notifications

### Port Configuration

Users can configure:
- **Motor Port** (A-F) - Where the motor is connected
- **Sensor Port** (A-F) - Where the sensor is connected
- **Sensor Type** - Color/Light, Force, or Distance

### Sensor Types

1. **Color Sensor** (color_sensor.reflection):
   - Returns 0-100 (dark to light)
   - Good for: light detection, line following

2. **Force Sensor** (force_sensor.force):
   - Returns 0-10 Newtons, scaled to 0-100%
   - Good for: button presses, touch detection

3. **Distance Sensor** (distance_sensor.distance):
   - Returns millimeters, scaled to 0-100% (far to close)
   - Good for: proximity detection, obstacle avoidance

## Program Generation

### Quick Control Program (Explore/Train)

Generated by `generateQuickControlProgram()`:

```python
import runloop
from hub import port
import motor
import color_sensor  # or force_sensor, distance_sensor

async def main():
    motor.run_to_absolute_position(port.A, 90, 1000)
    value = color_sensor.reflection(port.B)
    print(f"SENSOR:{value}")

runloop.run(main())
```

### k-NN Program (Play Mode)

Generated by `generateKNNProgram()`:

```python
import runloop
from hub import port
import motor
import color_sensor

sensor_data = [10, 50, 90]
motor_data = [180, 90, 20]

def find_nearest(value):
    min_diff = float('inf')
    nearest_idx = 0
    for i, s in enumerate(sensor_data):
        diff = abs(value - s)
        if diff < min_diff:
            min_diff = diff
            nearest_idx = i
    return motor_data[nearest_idx]

async def read_sensor():
    value = color_sensor.reflection(port.B)
    return value

async def main():
    while True:
        sensor_value = await read_sensor()
        target_position = find_nearest(sensor_value)
        motor.run_to_absolute_position(port.A, target_position, 800)
        print(f"SENSOR:{sensor_value} MOTOR:{target_position}")
        await runloop.sleep_ms(100)

runloop.run(main())
```

## Usage Instructions

### For End Users

1. **Connect to Spike Prime**:
   - Click the Bluetooth button in your app
   - Select your Spike Prime hub
   - Wait for connection

2. **Configure Ports**:
   - Set Motor Port (e.g., A)
   - Set Sensor Port (e.g., B)
   - Choose Sensor Type

3. **Explore Mode**:
   - Move the motor slider to control the motor
   - Watch sensor readings update in real-time
   - Experiment with different motor positions

4. **Train Mode**:
   - Position the motor and observe sensor reading
   - Click "Add Value" to save the pair
   - Repeat to build a dataset (minimum 2 points)
   - Delete unwanted values with the × button
   - Watch the graph show your training data

5. **Play Mode**:
   - Click "Start" to run the autonomous program
   - The robot will continuously:
     - Read the sensor
     - Find the nearest training point
     - Move the motor to match
   - Click "Stop" to halt the program

## Troubleshooting

### "Motor not detected on port X"
- Check physical connection
- Verify correct port letter selected
- Reconnect the motor

### "Sensor not detected on port X"
- Check physical connection
- Verify correct sensor type selected
- Try changing sensor type and back

### "Upload failed"
- Check Bluetooth connection
- Try disconnecting and reconnecting
- Ensure Spike Prime battery is charged

### Sensor readings seem stuck
- Stop and restart the program
- Check sensor is working (test in LEGO app)
- Verify correct sensor type selected

### Motor doesn't move
- Check motor port configuration
- Ensure motor is plugged in securely
- Battery may need charging

### Program takes a while to respond
- This is normal - uploads take 1-2 seconds
- Debouncing delays motor updates by 500ms
- Wait for "Program running" status

## Extending the System

### Add New Sensor Types

1. In `smartMotorUtils.js`, add sensor type to `getSensorLabels()`:

```javascript
case 'temperature':
    return { low: 'Cold', high: 'Hot', icon: '🌡️' };
```

2. Add sensor reading code in `generateQuickControlProgram()` and `generateKNNProgram()`:

```javascript
if (sensorType === 'temperature') {
    code.push("import temperature_sensor");
    code.push(`value = temperature_sensor.temperature(port.${sensorPort})`);
    code.push("print(f\"SENSOR:{value}\")");
}
```

### Modify k-NN Algorithm

Edit the `find_nearest()` function in `generateKNNProgram()` to:
- Use k>1 neighbors
- Add weighted averaging
- Implement different distance metrics

### Add Data Persistence

Store training data in localStorage:

```javascript
// Save
localStorage.setItem('trainingData', JSON.stringify(trainingData));

// Load
const saved = localStorage.getItem('trainingData');
if (saved) {
    setTrainingData(JSON.parse(saved));
}
```

## Performance Considerations

### Upload Frequency
- Debounce time: 500ms (adjustable in `handleMotorChange`)
- Each upload takes 1-2 seconds
- Too many uploads can overwhelm the hub

### Training Data Size
- Recommended: 3-10 points
- Maximum: ~50 points (program size limits)
- More points = slower nearest neighbor search

### Play Mode Updates
- Default: 100ms loop (10 Hz)
- Adjustable in generated program
- Faster = more responsive, more battery usage

## API Reference

### SmartMotorSpike Component Props

The component doesn't take props - it uses BLE context internally.

### Key Functions

#### `uploadAndRunProgram(programBuffer)`
Uploads and runs a program on slot 0.

#### `generateQuickControlProgram(motorPort, motorPosition, sensorPort, sensorType)`
Creates a simple program for motor control and sensor reading.

#### `generateKNNProgram(motorPort, sensorPort, sensorType, trainingData)`
Creates a k-NN program for autonomous control.

#### `parseSensorMessage(message)`
Parses console notifications: `"SENSOR:50"` or `"SENSOR:50 MOTOR:90"`

## Comparison with Original Smart Motor

| Feature | Original (ESP32/WebUSB) | Spike Prime (BLE) |
|---------|------------------------|-------------------|
| Connection | WebUSB | Web Bluetooth |
| Communication | Bidirectional serial | Program upload + notifications |
| Response Time | <50ms | ~1-2 seconds |
| Motor Control | Direct commands | Program-based |
| Sensor Reading | Polling | Console notifications |
| Training Storage | On device | In browser |
| Play Mode | Real-time k-NN | On-device k-NN |

## Known Limitations

1. **Upload Latency**: 1-2 seconds per program upload
2. **Debounce Required**: Can't update too rapidly
3. **No Direct Motor Control**: Must upload programs
4. **Sensor Sampling**: ~100ms in Play mode
5. **Training Data**: Limited by program size (~50 points max)
